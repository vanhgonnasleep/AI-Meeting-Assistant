2.0 Executive Overview

In modern corporate and educational environments, meetings consume up to 30% of working hours, yet extracting actionable insights remains manual, error-prone, and inefficient. While commercial cloud solutions (e.g., Otter.ai, Microsoft Copilot) exist, they present severe data privacy vulnerabilities and significant recurring subscription costs. Transmitting internal financial deliberations, intellectual property discussions, and personnel reviews to cloud APIs violates enterprise security guidelines (e.g., GDPR, SOC 2).

AI Meeting Assistant solves this paradigm by delivering an enterprise-ready meeting transcription, summarization, and action item tracking platform engineered to run 100% offline on standard consumer hardware (laptops with 8GB–16GB RAM, with or without dedicated NVIDIA GPUs). The system combines state-of-the-art automatic speech recognition (OpenAI Whisper) with a novel Hybrid Extractive-Abstractive Summarization approach: a high-speed vector-space algorithm (Maximal Marginal Relevance) pre-filters conversational noise before feeding high-density decision points into a local Large Language Model (Meta Llama 3) via a sliding-window Map-Reduce architecture.

3.0 Problems and Objectives

3.1 Problem Statement

  1. Confidentiality and Privacy Risks: Enterprise and academic stakeholders cannot upload proprietary audio records to third-party cloud LLM endpoints without risking data leakage and regulatory non-compliance.
  2. Hardware and Memory Bottlenecks on Edge Devices: Consumer laptops lack data-center VRAM (e.g., A100 GPUs). Running 8-billion parameter models directly over raw multi-hour transcripts triggers Out-Of-Memory (OOM) failures or intolerable latency (often >15 minutes per file).
  3. Conversational Redundancy and Disfluency: Human speech contains 40%–50% lexical noise, verbal fillers ("um", "uh", "you know"), greetings, and circular arguments. Injecting raw speech directly into an LLM exhausts the context window and triggers hallucination.
  4. System Brittle Failures during Live Operations: Long-running synchronous AI calls can freeze backend event loops, causing browser network timeouts and presentation crashes when demoed on low-spec hardware.

3.2 Project Objectives

  • Zero-Cloud Guarantee: Build a self-contained local desktop system with zero external API calls for audio transcription, text summarization, or structured storage.
  • Algorithmic Compression (≥35%): Implement a pure-Python Maximal Marginal Relevance (MMR) filter that mathematically eliminates repetitive speech without losing critical decision statements.
  • Scalable Map-Reduce Pipeline: Design an overlapping sliding-window chunking strategy capable of processing transcripts of arbitrary length (1–3 hours) within a constrained 2048/4096 token budget.
  • Robust Data Contracts & Defensive Engineering: Guarantee that malformed model outputs (e.g., invalid JSON syntax from quantized models) are sanitized automatically without crashing the user interface.
  • Production-Grade UX: Deliver an interactive React dashboard with dual transcript switching (Raw vs. Filtered), live telemetry metrics, task completion checklists, and persistent SQLite history.

4.0 Technical Approaches & Trade-Off Analysis

4.1 Technology Stack & Architectural Selection

  • Speech-to-Text Engine: OpenAI Whisper (tiny model for CPU-only laptops; base model for NVIDIA CUDA-accelerated systems). Audio is converted into Log-Mel spectrogram representations (80-channel filterbank) and processed via an encoder-decoder sequence-to-sequence Transformer.
  • Extractive Algorithmic Layer: Pure-Python Vector Space Model employing Sparse TF-IDF and Maximal Marginal Relevance (MMR). Evaluates relevance to a meeting centroid vector Q while penalizing cosine similarity against already selected sentences.
  • Abstractive Summarization Engine: Meta Llama 3 (8B quantized or Llama 3.2 1B/3B) running on local Ollama, orchestrated through a sliding-window Map-Reduce pipeline.
  • Structured Task Extraction: Constrained JSON prompt format paired with a custom Lexical Bracket-Depth Scanner and single-to-double quote recovery filter.
  • Persistence Layer: Embedded SQLite 3 configured with Write-Ahead Logging (WAL) mode and a 15-second busy timeout for thread-safe asynchronous concurrency.
  • Client Layer: React 19 single-page application bundled with Vite 8 and styled using Tailwind CSS utility classes.

4.2 Core Mathematical Formulation: Maximal Marginal Relevance (MMR)

Given candidate sentence pool R, currently selected summary pool S, and meeting document centroid vector Q, the next sentence s* is iteratively extracted via:

MMR(s)  =  arg maxsi ∈ R \ S [ λ · Sim1(si, Q) − (1 − λ) · maxsj ∈ S Sim2(si, sj) ]

Where Sim(u, v) = u · v∥u∥ ∥v∥, and hyperparameter λ = 0.65 balances 65% topical significance against 35% anti-redundancy penalty. This achieves O(V·N + K·N) complexity, eliminating the O(N2) graph overhead of TextRank.

4.3 Engineering Trade-Offs Matrix

Architectural Decision Selected Approach & Advantages Compromise / Mitigation Strategy
System Architecture:
Modular Monolith vs. Microservices / Celery		 FastAPI Modular Monolith: Minimal memory overhead (saves 1.5–3GB RAM otherwise needed for RabbitMQ/Redis daemons); zero-copy memory transfers; ideal for local single-node computing. Lacks horizontal multi-node scaling. Mitigated by using worker threadpools (run_in_threadpool) and SQLite WAL mode for thread-safe concurrent reads.
Summarization Paradigm:
Pure Extractive vs. Abstractive vs. Hybrid		 Hybrid MMR + Map-Reduce: MMR compresses transcript by ~40% in <50ms without hallucination; Llama 3 then synthesizes fluent executive bullet points from dense text. Requires two-stage processing. Mitigated by the fact that MMR execution time (0.02s) is negligible compared to STT/LLM inference time.
Model Execution:
Cloud API (GPT-4) vs. Local LLM (Llama 3)		 Local Ollama Deployment: 100% data sovereignty; zero per-token cost; offline operational autonomy. Lower reasoning capacity compared to frontier cloud models. Mitigated by strict prompt engineering and few-shot formatting.

5.2 Inference Safeguard Logic Flow

To prevent software freezes on arbitrary presentation machines, the pipeline implements a 3-tier fail-safe: (1) Pre-flight Hardware Resolution: Queries nvidia-smi to automatically bind either Llama 3 8B (GPU) or Llama 3.2 1B (CPU); (2) Inference Timeout Guard: A 35-second timeout on Ollama calls automatically falls back to an adaptive deterministic summary if CPU starvation occurs; (3) Instant Showcase Bypass: The frontend exposes a 50ms demo path returning pre-computed meeting analytics for emergency live presentation continuity.
