# Meeting workspace design

The owner approved the roadmap: review/edit minutes, manage tasks across meetings, improve retrieval, and connect meetings by project. They authorize direct integration into main and GitHub push after verification. Preserve local single-user operation and existing meeting data. No external sharing, audio retention, realtime recording, background-job subsystem or accounts in this increment.

## Data and contracts

Extend meetings non-destructively with revision INTEGER default 0, review_status TEXT default draft, project_id INTEGER nullable. MeetingRecord and detail responses expose these fields. Any existing content/task/speaker write increments revision and resets review_status to draft; chat appends/clears do not change content revision. Optimistic updates return 409 on mismatch, 404 on missing resource, and never partially apply.

New database/workspace.py owns review, project and task operations. ai-summary-service/workspace_api.py exports create_workspace_router(summary_function), included by main; summary_function is main.summarize_with_llama (dependency callback). All tests use existing temporary DB fixtures. New UI components live in src/Workspace.jsx and src/MeetingEditor.jsx.

* PATCH /api/meetings/{id}/review: {expected_revision, review_status: draft|reviewed, raw_transcript?: string, segments?: array, executive_summary?: string, action_items?: array, insights?: object}. Return {meeting: full record}. Segments supplied regenerate raw_transcript with attribution; raw text supplied alone clears stale segments. Source changes clear chat and old insights unless replacement insights supplied, reset review status to draft even if reviewed requested; user reviews corrected result separately. Summary/task/insight edits invalidate prior review. An unchanged record may be explicitly marked reviewed. Text edits do not pretend automatic regeneration. Segments preserve start/end metadata. Empty collections are valid. Bound payload lengths compatible with chat budgets; task text nonempty up to 4000, assignee up to 128, deadline up to 128, statuses pending|in_progress|completed|done. Insight objects retain source metadata; decision.status allows proposed|approved|superseded|cancelled, default proposed when edited. Do not interpret machine extraction as human approval.
* POST /api/meetings/{id}/regenerate-summary: {expected_revision, model: string default auto}. Read source snapshot, generate summary, then guarded write draft. Reject empty/failed model output without changing record; reject concurrent edits. Source unchanged, no automatic task/insight regeneration. Admission limits apply.
* GET /api/tasks?q=&status=&assignee=&project_id=&limit=50&offset=0: {tasks:[{meeting_id, filename, revision, project_id, task_idx, task, assignee, deadline, status}], total, has_more, offset, limit}. Search literal Unicode casefold before pagination; scan only task columns in bounded batches. Deterministic newest-meeting/index ordering. Task row opens source meeting for editing; existing status endpoint remains compatible.
* GET /api/projects: {projects:[{id,name,meeting_count}]}.
* POST /api/projects: {name}, return {project:{id,name,meeting_count:0}}; trimmed 1..128 chars, reject duplicates case-insensitively 409.
* PATCH /api/meetings/{id}/project: {expected_revision,project_id: integer|null}, return {meeting}. Assignment increments revision, preserves content/review; verify project exists.
* GET /api/projects/{id}/timeline?limit=50&offset=0: {entries:[{meeting_id,filename,created_at,revision,review_status,decision_idx,text,status,timestamp?,speaker?,start?,end?}],total,has_more,offset,limit}. Timeline follows stored decision history across meetings. Human edits status; no automatic assertion that two differently phrased decisions are the same or contradictory. Selecting source opens its meeting.

## UI

Header Workspace button opens tasks/projects modal, available with or without loaded result. Filters and pagination; explicit busy/error/empty states, invalidate stale responses on filter/tab change/close. Projects can be created and timeline opened. Loaded saved meeting toolbar offers Edit & review and project assignment. Editor fetches latest detail, preserves metadata, edits transcript by segment when present, summary, tasks and insight text/decision statuses; save, review and regenerate summary are distinct actions. API 409 preserves draft and offers reload rather than overwriting. On successful save/update replace current result and task statuses/chat from server, cancel stale session requests. Demo and unsaved results cannot edit persisted records.

## Retrieval

Chat payload adds semantic:boolean default false, embedding_model:string default embeddinggemma (max128). Both chat endpoints propagate these; UI checkbox and model name input. Hybrid retrieval combines existing lexical rank with cosine nearest excerpts using reciprocal rank fusion. Semantic rank requires cosine>=0.45; score is similarity, not calibrated confidence. Ollama /api/embed runs locally with finite timeout, bounded batches, bounded chunk count, bounded LRU embedding cache by model+content hash. Verify vector count, dimension, finiteness and nonzero norms; malformed/unavailable output falls back to lexical with an explicit retrieval warning. No embeddings from generated summaries. Quoted questions embed their quoted source anchor. Overview sampling remains unchanged. Returned citations retain exact source metadata. No new dependency. Threshold and model need representative evaluation, not claimed accuracy.
